## Section 5 章节导言（完整翻译）

**Models and Evaluations。** 作者在 LLaMA-3.1 Instruct（8B）与 Qwen3（4B、8B、Coder-30B-A3B-Instruct）预训练模型上开展实验。任务包括：数学的 GSM8K（Cobbe et al., 2021）、MATH（Lightman et al., 2023）和 AIME25（MAA, 2025）；代码的 HumanEval（Chen, 2021）、MBPP（Austin et al., 2021）和 LiveCodeBench（Jain et al., 2024）；聊天的 MT-Bench（Zheng et al., 2023）和 Alpaca（Taori et al., 2023）。使用平均接受长度 \(\tau\) 和对自回归基线的端到端解码加速比评价每项任务。除非特别指出，实验使用 NVIDIA H200 GPU。

**Datasets。** 为获得多样化训练数据，从 NVIDIA Nemotron Post-Training Dataset V2（Nathawani et al., 2025）与 CodeAlpaca（Chaudhary, 2023）收集约 80 万条混合样本。为了更好地与目标模型对齐，作者不直接使用原数据集 Response，而使用 Target Model 生成的 Response 构建训练数据。

**Implementation。** DFlash Draft Model 使用 5 层（Qwen3 Coder 使用 8 层），Block Size 16（LLaMA 3.1 使用 10）。目标模型隐藏特征从第二层至倒数第三层间均匀选取的 5 层中提取。其他训练细节见附录 A.1。

**Baselines。** 对比原生自回归解码和 EAGLE-3（Li et al., 2025b）。其他基于 dLLM 的推测解码方法（Liu et al., 2025; Samragh et al., 2025; Li et al., 2025a; Sandler et al., 2025）没有可用开源实现，未加入比较。Qwen3 对照使用 AngelSlim（Tencent, 2025）发布的 EAGLE-3 Checkpoint；LLaMA-3.1-Instruct 使用 EAGLE-3 团队官方 Checkpoint。

## 5.5 Ablation Study（完整翻译）

**导言。** 本节对训练数据和若干 DFlash 架构设计做消融。除非另行说明，模型均使用来自完整混合数据中随机抽取的 100K 样本。除 SGLang 测试外，实验均采用单张 H200 GPU 与 Greedy Decoding。

### 5.5.2 Number of Draft Layers（完整翻译）

**第 1 段（跨第 8 页左右栏）。** DFlash 的接受长度能够随 Draft 层数增加而改善，但更深模型虽有更强的表达能力、获得更长接受长度，也增加 Draft 延迟，因此最佳层数依赖部署环境。如 Table 6 所示，8 层虽然接受长度最长，但 5 层因生成成本与质量的平衡更好而达到最高平均加速比。

**Table 6 完整表注翻译：** 五层 Draft Model 具有最佳平均加速；全部模型使用 Block Size 16，并从目标网络五层提取特征。每格是“加速比 / \(\tau\)”。

| Draft 层数 | Math500 | HumanEval | MT-Bench |
|---|---|---|---|
| 3-L | 4.69× / 5.64 | 3.90× / 4.61 | 2.38× / 3.18 |
| 5-L | 4.71× / 5.99 | 3.96× / 4.94 | 2.35× / 3.37 |
| 8-L | 4.64× / 6.33 | 3.96× / 5.29 | 2.23× / 3.50 |

**独立分析。** \(\tau\) 随 3→5→8 层在三任务上持续增长，整体加速却不是单调的。三个任务的加速比算术平均分别约为 3.657×、3.673×、3.610×。5-L 比 3-L 略快，但 MT-Bench 上 3-L 的 2.38× 反而高于 5-L 的 2.35×。不能认为五层在所有部署场景绝对最佳。

### 5.5.3 Number of Target Hidden Features（完整翻译）

**第 1 段。** 从目标模型提取的隐藏特征数量影响接受长度与端到端加速。更多层的特征提供更多语义和未来 Token 信息，提高草稿质量。Table 7 显示使用五层隐藏特征比使用三层好，但增加了训练开销，尤其离线训练时缓存 Target Hidden States 的容量随层数线性增加。

**Table 7 完整表注翻译：** 更多 Target Hidden Features 提高接受长度；全部 Draft 模型使用 3 层和 Block Size 16。每格是“加速比 / \(\tau\)”。

| Target Features | Math500 | HumanEval | MT-Bench |
|---|---|---|---|
| 3-H | 4.49× / 5.38 | 3.80× / 4.47 | 2.32× / 3.07 |
| 5-H | 4.69× / 5.64 | 3.90× / 4.61 | 2.38× / 3.18 |

**独立分析。** Math500 的加速比从 4.49× 到 4.69×，提升约 4.5%；如缓存每层相同形状的特征，缓存三层到五层的原始量增幅约 66.7%，但实际存储受压缩及实现影响。论文只测试了 3-H/5-H，不能证明 5 是全局最优值。

| 8 | 16 | 3.78× / 5.02 | 3.24× / 4.28 | 2.09× / 3.09 |
| 8 | 8 | 3.97× / 5.21 | 3.53× / 4.61 | 2.22× / 3.29 |

**第 2 段（跨到第 9 页）。** 当训练/推理 BS 一致（8→8 或 16→16），BS=16 在数学及代码任务上拥有显著更长的接受长度。Math500 的接受直方图发现 BS=8 模型有 35.7% 的情况完整接受整个草稿块，说明该块大小时常未能发挥可用预测能力；BS=16 的接受长度分布更加广泛，平均接受长度更高，能够更有效利用较大块。

**第 3 段。** 跨块大小的泛化表现存在不对称性：大 BS 训练的模型能较好泛化到较小的推理 BS。训练 BS=16、推理 BS=8 的接受长度接近训练/测试都使用 BS=8 的模型，而反过来并不成立。

**第 4 段。** 大 BS 训练、小 BS 推理的可行性，为未来自适应 Block-size Scheduling 提供依据。真实 Serving 场景中，例如大 Batch 导致 Compute-bound，较大的块可能增加验证成本；适时缩小块能够改善加速比。作者将自适应块调度留作未来工作。

**独立分析。** 结合第 3 节公式，推理时可以探索

\[
B^*=\arg\max_B \frac{\tau(B)}{T_{\mathrm{draft}}(B)+T_{\mathrm{verify}}(B)}.
\]

这是独立的负载自适应方案，不是本文已实现的调度器。Table 8 并未证明高并发下 BS=8 一定优于 BS=16，最优值需要根据资源竞争、接受率和验证开销实测。

### 5.5.5 KV Injection vs. Input Fusion（完整翻译）

**第 1 段。** 本项消融比较两种目标特征条件化：像 EAGLE-3 那样只在输入层进行融合，或者作为 KV Entries 注入每个 Draft Layer。在自回归 Drafting 和块扩散 Drafting 两种设置下分别比较，见 Table 9。

**Table 9 完整表注翻译：** Qwen3-4B 上的目标特征条件化消融，Draft Model 使用 5 层、Draft Block Size 8。注意：Table 9 每个任务格的指标顺序为“\(\tau\) / 加速比”，与 Table 6–8 相反。

| Draft 方式 | Variant | Injection | GSM8K | HumanEval | MT-Bench |
|---|---|---|---|---|---|
| Autoregressive | EAGLE-3-5L | Input | 4.2 / 2.1× | 4.3 / 2.2× | 3.1 / 1.4× |
| Autoregressive | DFlash-AR | KV | 4.8 / 2.4× | 4.6 / 2.3× | 3.4 / 1.5× |
| Block-diffusion | DFlash | Input | 3.5 / 2.9× | 3.5 / 2.9× | 2.6 / 2.0× |
| Block-diffusion | DFlash | KV | 4.2 / 3.3× | 4.0 / 3.2× | 3.0 / 2.2× |

**第 2 段（跨到第 9 页右栏）。** KV Injection 比 Input Fusion 更有效：在自回归 Draft 中，DFlash-AR 接受长度在所有任务上均优于 EAGLE-3-5L；在块扩散 Draft 中，逐层 KV 注入也使各任务的接受长度优于只做 Input Fusion。因而每个草稿层都能读取目标特征 KV，比只在输入层注入目标信息更好。

**第 3 段。** DFlash 与 EAGLE-3-5L 具有相当的接受长度，但块扩散能够并行草稿预测多个 Token，因此加速显著高于 EAGLE-3-5L。DFlash 同时受益于逐层 KV 注入的强条件化，以及并行 Drafting 的低延迟。

**独立分析。** GSM8K 中，保持块扩散不变，由 Input Fusion→KV Injection，\(\tau\) 从 3.5→4.2，加速 2.9×→3.3×。保持 KV Injection 不变，DFlash-AR 的 \(\tau=4.8\) 高于块扩散 DFlash 的 4.2，但前者加速 2.4× 低于后者 3.3×，说明低 Draft 延迟可抵消一定的接受长度差距。本文没有给出各层信息稀释的直接表示分析，不能把“KV 更有效”直接等同于对信息稀释机理的独立数学证明。

## 端到端实验分析与研究限制（独立分析）

1. **质量保证与 Draft 预测不是一回事。** 论文强调 Target 验证维持目标输出分布；接受长度高不意味着 Draft Model 可以独立达到 Target 的完整任务准确率。
2. **不能混合实验后端。** Table 1/2 是 Transformers；Table 3 是 B200+SGLang+FA4+Spec-v2；Table 5 是 B200+SGLang+FlashInfer+Spec-v1。不同后端和调度不可直接归因。
3. **Serving 中加速比与吞吐量不同。** 高并发下相对倍数可能降低，而绝对 TPS 仍显著增加。
4. **长上下文仅提供接受长度。** Table 4 没有验证端到端吞吐或延迟提升幅度；不可将接受长度相对提升等同加速。
5. **层数与特征数均有成本。** 5-L 是本组平均速度最好的层数，不是所有任务最优；5-H 比 3-H 更好但要付出特征缓存/训练成本。
6. **较大训练 BS 的向下泛化有利于部署弹性。** 动态 BS 是论文明确指出的未来研究方向，不能伪称已经实现。
7. **两个独立结构贡献。** Table 9 支持 KV Injection 改善接受长度、块扩散并行 Drafting 降低延迟，两者互补。
8. **外部比较覆盖有限。** 原文说明因开源实现不足，没有与全部相关 dLLM speculative decoding 方法直接比较。
