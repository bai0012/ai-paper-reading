## 完整中文翻译

**原文第 1 段：自回归生成瓶颈**

大语言模型（Large Language Models, LLMs）已经支持多种强大的应用，包括对话智能体（Yang et al., 2025; Guo et al., 2025）与自动化编程工具。然而，尽管取得了这些成功，LLM 推理仍主要由逐 Token 的串行生成过程主导，每一个输出都依赖此前的完整上下文。这种固有的串行性形成了重大的性能瓶颈：推理速度缓慢、受内存带宽限制（memory-bound），无法充分利用现代 GPU。随着长思维链（Chain-of-Thought, CoT）推理模型（OpenAI et al., 2024; Guo et al., 2025）近期兴起，这一瓶颈愈发关键，因为漫长的推理时间现在主导了生成过程。

**原文第 2 段：推测解码的局限**

推测解码（Speculative Decoding）（Leviathan et al., 2023; Li et al., 2025c; 2024; 2025b; Cai et al., 2024）已成为解决这一瓶颈的主要方案。这一范式使用轻量的草稿模型（Draft Model）推测一段未来 Token，再由较大的目标模型（Target Model）并行验证。尽管这种方法能够实现无损加速，且已经被广泛集成到生产框架中，但 EAGLE-3（Li et al., 2025b）等最先进的方法依然依赖自回归草稿生成。这种串行 Draft 过程不仅天然低效，而且容易产生误差累积，从而使实际可达的加速比被限制在大约 2–3 倍。

**原文第 3 段：扩散语言模型的潜力与质量问题**

最近，扩散大语言模型（Diffusion LLMs, dLLMs）（Nie et al., 2025）通过并行文本生成及双向上下文建模，为自回归语言模型提供了一种有前景的替代路径。块扩散模型（Block Diffusion Models）（Arriola et al., 2025; Cheng et al., 2025; Wu et al., 2025）能够对一个 Mask Token 块同时去噪。但当前开源 dLLM 的生成质量通常不及自回归模型。此外，要维持可以接受的输出质量往往需要大量去噪步骤，这显著削弱其原本的推理速度（Qian et al., 2026）。

**原文第 4 段：组合两种范式**

上述格局揭示了一个关键权衡：自回归模型生成质量更好，却受到串行延迟限制；扩散模型可以快速并行生成，但通常需要以准确性为代价。由此自然产生研究问题：我们能否组合两种范式的长处，同时减轻各自的弱点？一个很有吸引力的方案是让扩散模型进行高速并行草稿生成，再让高质量自回归模型进行验证，从而确保最终输出仍然无损。

**原文第 5 段：现有扩散 Draft 方法的问题**

然而，利用扩散模型进行草稿生成并不简单，现有方法要么不够实用，要么只获得有限加速。DiffuSpec（Li et al., 2025a）和 SpecDiff-2（Sandler et al., 2025）等方法采用庞大的草稿模型（例如 7B 参数）。这种巨大的内存占用在真实在线服务中常常成本高得难以接受。虽然这些大型 Draft Model 可以产生质量较高的候选 Token 和较长的接受长度，但草稿生成自身的高延迟，使实际加速比只能达到较为有限的 3–4 倍。与此不同，PARD（An et al., 2025）训练较小的自回归模型模仿扩散式并行生成，然后为目标 LLM 进行推测解码。但这些小模型缺乏目标模型的建模能力，导致接受长度受限，加速上限约为 3 倍。

**原文第 6 段：研究问题重申**

难道真的不存在“免费的午餐”（no free lunch）吗？我们能否构建一种既轻量又高度准确的扩散草稿模型？

**原文第 7 段：DFlash 方案**

本文提出 DFlash：一种使用轻量块扩散模型，同时实现高速、高质量草稿生成的推测解码框架。核心洞察非常简单：**目标模型最了解任务（the target knows best）**。如 Samragh et al.（2025）所发现的那样，大型自回归 LLM 的隐藏特征隐式地包含对多个未来 Token 的信息。DFlash 使用这些隐藏特征作为上下文，使 Draft Model 能够以此为条件并行预测未来的 Token 块。实际上，草稿模型转变为一个扩散适配器（diffusion adapter），能够高效利用大模型已经建模的深层上下文特征。DFlash 并不要求小型草稿模型从零开始推理，而是融合目标模型的推理能力与轻量扩散草稿模型的并行生成速度。

**原文第 8 段：实验结果与展望**

作者在广泛的模型和基准测试上评估 DFlash，并使用 SGLang（Zheng et al., 2024）在贴近真实场景的服务部署设置下展示实际收益。如 Figure 1 所示，在 Qwen3-8B（Yang et al., 2025）上，DFlash 最多实现约 6.1 倍加速，并且在大部分基准测试上接近先进方法 EAGLE-3 速度的 2.5 倍。作者认为，DFlash 在加速 LLM 推理以及普及高性能 AI 方面向前迈出了重要一步。

## 技术讲解（独立分析，不属于逐段原文）

### 1. AR 生成为什么低 GPU 利用率

生成每个下一个 Token 时必须完成当前步再提交给下一步；batch 小时，解码常受到 KV cache 的读取和模型权重访存影响。在一次 Draft 中连续调用 γ 次 Forward，使延迟随 γ 增加。这里 memory-bound 是一种典型运行条件，不是对任意部署场景绝对成立的断言。

### 2. 扩散为什么更适合 Draft，而不是单独负责最终输出

块内 Mask Token 可以通过双向上下文一次预测多个位置；但一次预测的草稿可能不符合 Target Model 分布。经正确的 Target 验证/采样后，即使 Draft 预测失败也不会改变目标分布，只损失效率。这解释了为什么草稿模型可以激进追求低延迟，而无需单独承担高质量生成的责任。

### 3. “Target knows best”的机制直觉

最终层 token logits 只显式描述下一个 Token；多层隐藏特征可能携带更丰富的语义、句法及未来 Token 信息。DFlash 让小型 Draft Model 使用目标模型特征，避免独立从零建模。第 4 节及附录 A.3 会进一步研究多层特征融合与逐层 KV 注入。

### 4. 不只看接受长度

实际有效加速取决于草稿延迟、验证成本、平均接受 Token 数及硬件/并发条件。大型 dLLM 的接受长度可能更好，但自身 Draft 太贵；小型 Draft 更快但质量不足。DFlash 的研究主张是通过目标特征条件化让更深的小型并行 Draft 模型在两者之间取得更好折衷。

### 5. 跨论文关联（待进一步对照原文）

- [EAGLE-3](https://arxiv.org/abs/2503.01840)：依赖目标特征，但 Draft 通常是自回归和树式候选；对比 DFlash 的一次性并行块预测。
- [PARD](https://arxiv.org/abs/2504.18583)：小草稿模型模拟并行生成；DFlash 的差异在于直接使用目标模型的内部特征。
- [Block Diffusion](https://arxiv.org/abs/2503.09573)：块内扩散的基础；DFlash 将其限制到 speculative draft 任务。
- [Your LLM Knows the Future](https://arxiv.org/abs/2507.11851)：目标隐藏特征可能携带多 Token 未来信息，为 DFlash 的条件化提供动机。
